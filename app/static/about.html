Method

How it works, and what it cannot see

A gradient-boosted model reads the live state of an innings and returns the total that innings will finish on. What follows is where the data comes from, how the features are built so that nothing sees its own future, and an honest account of the limits.

The data

Cricsheet, ball by ball

Every match is a JSON file recording each delivery: who bowled it, who faced it, what it cost, and whether anyone got out. Nothing here is scraped or estimated — it is the scorer's record.

Features

Nothing may see its own future

Each row describes one moment in one innings. Some of what it describes is visible on the scoreboard; the rest is context the model has to be told. The context is where a prediction model usually starts cheating.

  1. What the scoreboard shows

    Runs, wickets down, legal balls bowled, current run rate, fours and sixes so far, the proportion of dot balls, runs in the last thirty deliveries, and — when the side is chasing — the target and how many runs are still needed. Balls are counted from the legal deliveries only; a wide is not a ball of the over, so counting overs times six would quietly misplace every state.

  2. How far through the innings it is

    The single idea that lets one model cover formats that look nothing alike. Rather than "twelve overs gone", the model is given the fraction of the innings that has been bowled. A T20 at ball 60 and an ODI at ball 150 are both halfway, and that is what the model sees. A multi-day innings has no ball limit, so the fraction is undefined and left missing — LightGBM sends those rows down their own branch rather than guessing a value for them.

  3. Context, as of the match date

    A ground's par score, a side's scoring history, a batter's strike rate and a bowler's economy are all averages — and an average taken over the whole dataset would include matches that had not happened yet. Every one of them is instead an expanding mean shifted by one match, so a row can only ever see fixtures played before it. Replacing any of these with a plain group average would leak the future and quietly improve every metric on the results page without improving the model at all.

  4. Context, per format

    Those same averages are computed separately for each format family. A ground's ODI par is not its T20 par; a batter's Test strike rate is not his T20 strike rate. Pooling them would be worse than having no feature at all, because it would hand a T20 row a Test-sized expectation and the model would answer accordingly.

  5. What is left missing on purpose

    A debutant has no career strike rate. Rather than fill that gap with an average, it is left empty — that a player has no record is itself information, and the model learns to treat those rows differently.

Evaluation

Trained on the past, tested on the future

Every ball of one innings carries the same answer — the total that innings finished on. Split those rows at random and ball 12.3 lands in training while ball 12.4 lands in testing: two nearly identical rows with the same answer. The model recalls rather than predicts, and the score looks excellent.

So matches are ordered by date and cut in time. The model trains on the earliest, tunes on the middle, and is judged only on matches played after both — the same position anyone would be in using it on a live game.

The split is by match date, so no innings is ever divided across two sets.

Uncertainty

The band, and how it is checked

A single projected number would imply a confidence nobody should have about a cricket innings. Every prediction therefore comes with a band that is meant to contain the true final score four times in five.

Producing that band takes two steps. Quantile models give a first estimate, but on their own they turn out to be far too narrow. So the model's errors on the validation matches are measured separately for each format and each quarter of the innings, and those measured errors set the width of the band instead. A band in the first over of a Test is not the same width as one in the last over of a T20, and it should not be.

The result is then checked against the test matches: how often does the band actually contain the answer? Both the target and the achieved figure are on the results page. An interval nobody measured is a decoration.

Limits

What it does not know

These are not caveats added for form. Each one is a real reason a prediction from this model can be wrong in a way it cannot anticipate.

No weather, no pitch

Rain, dew under lights, a green seaming surface or a worn fifth-day pitch are all absent from the data. A ground's par score absorbs some of this on average and none of it on the day. An innings played on an unusual surface will be predicted as though the surface were typical.

No team sheet

The model knows which sides are playing, not who is in them. A team missing its three best batters is, to this model, the same team. Individual form enters only through whoever happens to be at the crease and bowling on that delivery.

Chases end early

A side chasing 160 that reaches it in the eighteenth over stops batting. Its final score is not what it could have made — it is where the match ended. Those innings are censored observations, and the model is trained on them as though they were completed totals, which biases second-innings predictions downward.

Multi-day innings are thinned

A Test innings can run past six hundred deliveries. Kept in full, multi-day cricket would dominate the training loss purely by row count, so only every fourth ball of a long innings is kept. The multi-day model therefore learns from a coarser view of an innings than the T20 model does.

Cricket keeps changing

A total that won a T20 match a decade ago would lose one now. The model is trained on the past and will drift as scoring rates move on. It needs retraining periodically, and its error on recent matches is the only honest guide to how it will do tomorrow.

Unfamiliar teams and grounds

A side or venue the model never saw in training falls back to a format-wide average. The prediction will still look confident and will be worth considerably less. Predictions are also floored at the current score and capped at a physically reachable total, because without those bounds an unfamiliar name can push the model somewhere impossible.

Taken together: this is a model of how innings like this one have tended to finish, not a forecast of how this particular innings will finish. Read the band, not just the number.
